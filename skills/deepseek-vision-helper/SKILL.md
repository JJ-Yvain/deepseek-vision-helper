# DeepSeek Vision Helper（已注入识图结果）

当上下文中出现 `[Vision result] ...` 时，把它当作你"看到"的图片内容。

## 处理策略

- **单图**：直接以识别结果为准回答（文字提取、报错含义、界面说明、图表/表格分析等），给出结论。
- **多图（`图1: ... 图2: ...`）**：注入的图 = 用户**最新一轮**发送的图（同一次发送的几张图同时识别，**无先后之分**，图号仅用于引用）。回答以这一轮图为整体、优先回答最新一轮的问题；若对话中提到更早的图（如"之前那张"），以对应轮次的注入内容回答。
- **识别数量提示**：注入出现"本轮共 N 张图，单次上限 X 张，已识别前 Y 张；其余未识别，可重发或调大 max_images"时，说明本轮有图未识别——告知用户，可让其重发或调大配置。
- **识别结果不完整/模糊**：
  - 如实说明识别结果中未包含的信息，**不要编造**。
  - 主动给出可操作建议：裁剪相关区域后重发、放大局部、换更清晰的截图，或请用户描述想看的特定部分（如"左上角报错文字"、"第三行代码"）。
  - 用具体问题引导用户补充（如"能否单独截一下弹窗？"），而不是泛泛说"看不清"。
- **识别结果被截断**：长描述可能带 `…(截断)` 标记，或注入末尾给出"完整结果已存至 <路径>"提示。**识别本身是完整的**：需要被截断部分的完整内容时，读取提示中的文件（`vision_hook.py` 同目录的 `results/` 下）即可获取全量，无需用户重发。
- **批量场景（几十张图）**：若用户要求分析大量图片，建议使用批量识图脚本（`python vision_hook.py --folder <目录> --out results.md`）把结果写入文件后按需读取，不要把几十段描述灌进对话上下文；或分批让用户发送。

## 更新

识别结果末尾出现 `⚠️ 检测到新版本 vX.Y.Z（当前 vX.Y.Z），回复"更新"即可自动更新` 时：

- **告知用户**有新版本，询问是否现在更新；用户不感兴趣则不打扰。
- 用户同意后：若脚本位于插件数据目录（环境变量 `ZCODE_PLUGIN_DATA` 存在）→ 提示通过 ZCode 客户端更新；否则运行更新器：
  `python <临时目录>/update.py`（从 `https://raw.githubusercontent.com/JJ-Yvain/deepseek-vision-helper/main/update.py` 下载到临时目录后执行，它会自动对比版本并同步，且保留用户的 config.json/state/日志）。
- 更新完成后提示：重启客户端或下次会话生效。

## 边界

- 不要在已有识别结果时重复说"我无法查看图片"。
- 识别结果已约束为**纯事实输出**（不含识别模型自己的分析、建议或反问）：一切判断、分析、行动决策由你（主模型）负责。
- 识别结果是视觉模型的描述，细节可能不准：关键信息（精确数字、代码、姓名）可提示用户以原图为准。
- **如果你能直接看到图片（原生多模态模型）**：直接看图回答即可，无需依赖 `[Vision result]`；
  两者并存时以原图为准，`[Vision result]` 仅作参考。
